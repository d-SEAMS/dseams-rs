# Contributing to dseams-rs

This file is the working contract for anyone changing this repository. The
README is for users of the crates; this file is for people editing them.

## What lives here and what does not

This repository holds the Rust crates on top of the d-SEAMS C API. The
engine, the C API (`libseams`, header `include/seams.h`) and the C++ oracle
the tests compare against live in
[d-SEAMS/seams-core](https://github.com/d-SEAMS/seams-core).

- A new analysis, a changed result, a C API function or enumerator, a reader
  for a new file format, or a bug inside libseams: change seams-core first.
  Bind it here once a seams-core commit carries it, and move the pin.
- A wrapper, an options struct, an iterator, an error message on the Rust
  side, the build script, docs or examples: change it here.
- Do not copy engine sources into this tree. The bundled build takes them
  from `dseams-sys/vendor/`, which `vendor.py` writes and git ignores.

## Layout

| Path | Contents |
|---|---|
| `Cargo.toml` | Workspace; shared package fields and the `dseams-sys` dependency |
| `seams-core.env` | `SEAMS_CORE_REPO` and `SEAMS_CORE_REF`, the seams-core tag CI and `vendor.py` use |
| `dseams-sys/src/lib.rs` | Raw declarations, generated by `gen_sys.py` from `seams.h`. Do not edit by hand |
| `dseams-sys/build.rs` | Finds or builds libseams |
| `dseams-sys/sources.txt` | Translation units the `bundled` feature compiles, relative to seams-core |
| `dseams-sys/vendor.py` | Fills `dseams-sys/vendor/` from the pinned tag and Eigen 3.4.0 |
| `dseams-sys/gen_sys.py` | Writes `src/lib.rs` from a `seams.h` |
| `dseams/src/lib.rs` | The safe crate (library name `seams`) |
| `dseams/tests/` | `ice.rs` (every wrapper), `cpp_match.rs` (against the C++ oracle), `data/` fixtures |
| `dseams/examples/` | `ice`, `minimal`, `ice_ih`, `lang_tasks`, `binding_overhead`; each has a test of its output |
| `docs/` | API page, tutorial and language-task page, included by the d-SEAMS docs |
| `changelog.d/` | Unreleased changelog fragments |
| `.github/workflows/ci.yml` | Builds seams-core at the pin and runs every check below |

## How dseams-sys finds libseams

`build.rs` takes the first that applies:

1. `SEAMS_LIBDIR` (or `SEAMS_LIB_DIR`): the directory with the shared
   libseams. `SEAMS_INCLUDE` is a path list of header directories.
2. Feature `bundled`: compile from `vendor/`, or from a seams-core checkout
   named by `SEAMS_SOURCE_DIR`.
3. pkg-config module `seams`, at least 2.14.0 and below 3.0.0.

A `seams_version.h` from another major release or an older minor one stops
the build. `DOCS_RS` skips linking. The directory of a shared library reaches
`dseams/build.rs` as `DEP_SEAMS_RPATH` and goes on the rpath of the tests and
examples.

## Build and test

Build seams-core at the pinned tag with tests enabled, then run the
checks from the repository root:

```bash
. ./seams-core.env
git -C ../seams-core checkout "$SEAMS_CORE_REF"
(cd ../seams-core && pixi run meson setup bbdir -Dwith_tests=true -Dwith_cli=false \
  && pixi run ninja -C bbdir src/libseams.so bindings/binding_oracle)

export SEAMS_LIBDIR=$PWD/../seams-core/bbdir/src
export SEAMS_INCLUDE=$PWD/../seams-core/include:$SEAMS_LIBDIR
export SEAMS_CPP_ORACLE=$PWD/../seams-core/bbdir/bindings/binding_oracle
export SEAMS_SOURCE_ROOT=$PWD/../seams-core
export OMP_NUM_THREADS=1

cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test -- --test-threads=1
cargo test --examples -- --test-threads=1
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
```

The bundled feature and the publish check:

```bash
python3 dseams-sys/vendor.py --source ../seams-core
cargo clippy --features bundled --all-targets -- -D warnings
cargo test --features bundled --test ice --examples -- --test-threads=1
cargo +1.85.0 build --features bundled --all-targets
cargo publish --workspace --dry-run --allow-dirty
```

Every check must pass before a change is called done. Fix the code under
test; do not skip, ignore, loosen or delete a test to get there. A test may
change only when the behavior it pins changes on purpose, and the commit says
so. Without `SEAMS_CPP_ORACLE` and `SEAMS_SOURCE_ROOT`, `cpp_match` prints
that it skipped; CI sets both, and so should a local run that touches an
analysis.

## When seams.h changes

1. Move `SEAMS_CORE_REF` in `seams-core.env` to a seams-core tag, or to a
   commit while that release is still untagged. Never a branch name.
2. `python3 dseams-sys/gen_sys.py ../seams-core/include/seams.h dseams-sys/src/lib.rs`
3. Wrap the new symbols in `dseams`, with a doctest each, and extend
   `tests/ice.rs` and `tests/cpp_match.rs`.
4. Update `sources.txt` if the link closure of `src/seams_api.cpp` changed.
5. CI fails if `src/lib.rs` differs from the generator output for the pinned
   header.

## Commits and changelog

- [Conventional Commits](https://www.conventionalcommits.org/):
  `feat`, `fix`, `docs`, `test`, `build`, `ci`, `refactor`, `style`, `chore`,
  with a scope where it helps (`feat(sys): ...`). One logical change per
  commit; formatter-only changes go in their own `style:` commit.
- ASCII punctuation in code, docs and commit messages. Comments say what the
  code does and why, in the present tense; history belongs in the commit.
- Every user-visible change adds a fragment to `changelog.d/`, named
  `<issue>.<type>.md` or `+<slug>.<type>.md`, where `<type>` is `added`,
  `changed`, `deprecated`, `removed`, `fixed` or `security`. See
  `changelog.d/README.md`.

## Releases

The crate version is the seams-core version it binds, and both crates share
it through the workspace.

1. seams-core tags the release (`vX.Y.Z` on d-SEAMS/seams-core).
2. Here: set `SEAMS_CORE_REPO=https://github.com/d-SEAMS/seams-core` and
   `SEAMS_CORE_REF=vX.Y.Z`, set `workspace.package.version` and the
   `dseams-sys` requirement in `Cargo.toml` and `version` in
   `CITATION.cff` to `X.Y.Z`, run
   `towncrier build --version X.Y.Z`, and wait for CI on that commit.
3. `python3 dseams-sys/vendor.py`, then `cargo publish -p dseams-sys --allow-dirty`
   (`vendor/` is generated and ignored, so cargo counts it as uncommitted).
4. `cargo publish -p dseams` once `dseams-sys` is on crates.io.
5. Tag `vX.Y.Z` here.
